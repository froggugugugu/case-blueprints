# Pitfalls — 3D プリント設計の落とし穴

このファイルは `case-blueprints` で生成されたプロジェクトにおいて、よくある失敗パターン(pitfall)と対処法を整理する。

実例から抽出した教訓を含む(GPS ロガーケース等)。

---

## 印刷時の落とし穴

### P1. 印刷向きの判断ミス

**症状**: 細部(文字 emboss、薄い壁、フィレット)が初層側にあると失敗しやすい

**原因**:
- 初層は接着力優先で粗くなりがち
- 細部は印刷終盤の方が形状が出やすい

**対処**:
- `case-spec.yaml` の `print_orientation` を見直す
- body は `bottom_down`(底を下)、lid は `top_down`(天を下)が基本
- 細部のある面が **印刷終盤** に来るように設定

### P2. オーバーハング・サポートの見落とし

**症状**: 蝶番ナックル、カラビナタブ、張り出し部位が崩れる

**原因**: 50° 以上のオーバーハングはサポート必須

**対処**:
- `slicer-notes.md` の「サポート」セクションで部位別判断
- 蝶番ナックルの上半分はブリッジング可(短いブリッジは PLA で問題なし)
- ツリーサポート / オーガニックサポートを優先

### P3. フィレット過多

**症状**: 印刷困難、強度低下、寸法ばらつき増加

**原因**: 過大な R を入れすぎ

**対処**:
- 外側角: 2-3mm が標準
- 内側角: 0.5mm 程度
- 手触り重視部位のみ大きめ R(底面エッジなど)

### P4. フォント細部の潰れ

**症状**: body_text feature の文字が読めない、潰れる

**原因**: 層高が大きすぎる、emboss_depth が小さい

**対処**:
- 層高 0.16mm 以下 → 細部が鮮明
- 層高 0.2mm → ほぼ問題なし
- 層高 0.28mm 以上 → 細部潰れの恐れ
- emboss_depth 0.6mm(0.2mm 層 × 3 層)を最低ライン
- 極細フォントは避ける

## 設計時の落とし穴

### P5. 嵌合クリアランス不足/過多

**症状**: 蓋が硬すぎる / ゆるい

**原因**: `lid.fit_clearance` の値

**対処**:
- 0.15 未満 → 固い: `fit_clearance` を 0.3 以上に増やして `generator.py` を再生成
- 0.2 → 標準(PLA)
- 0.3 以上 → ゆるい: 0.2 程度に下げて再生成
- PETG は摩擦が大きいので 0.25 推奨
- **原則**: 実物でのやすり調整に逃げず、CAD で解決する(再現性が保たれる)

### P6. CAD 上の幾何重なり

**症状**: validator / fit-check で「○○ mm³ の重なり」を検出

**原因**: 蝶番ナックルなど、エッジを共有する設計で発生しやすい

**対処**:
- **CAD で解消するのが原則**。重なりの原因(エッジ共有・許容差・座標計算)を特定し、設計で逃がす(クリアランス、リリーフカット、座標オフセット)
- 構造上避けられないことが明らかな場合のみ、`fit_check.py` の `ALLOWLIST` に label / max_mm3 / 理由を併記して登録(P16 参照)
- 「実物で削れば OK」という暗黙許容は避ける(再現性を損なう、利用者への負担、テンプレートの完全性が低下)

### P7. 内寸計算ミス

**症状**: オブジェクトがケースに入らない、または隙間が大きすぎる

**原因**: 公差・余裕・ケーブル湾曲分の計算漏れ

**対処**:
- 内寸 = オブジェクト寸法 + 公差(`tolerance`) + 余裕(`internal.object_clearance`)
- ケーブルがある場合 `internal.cable_bend_allowance` を追加
- 複数オブジェクト時は配置間隔も加算

### P8. オブジェクト同士の干渉

**症状**: 配置時にコネクタ・ボタン・LED が他のオブジェクトと重なる

**原因**: `input/objects/<id>.yaml` の notes に向きを書いていない

**対処**:
- notes に「正面」「USB ポートの位置」「LED の位置」を明記
- `case-spec.yaml` の `objects[].note` に配置意図を残す
- validator で干渉チェック(features 別)

### P13. 蝶番の壁埋込でリリーフカット忘れ

**症状**: ピンを通した蝶番組立時、蓋が本体内に入らず干渉する

**原因**: 本体側ナックル円柱が壁に食い込む設計の場合、**蓋ナックル Z 位置でも本体壁が solid に存在**する。蓋シリンダーがその壁と干渉する。

**対処**:
- 蓋ナックル Z 位置で本体壁に **円筒状のリリーフカット**(半径 `knuckle_r + body_relief_clearance`)を追加
- `case-config.yaml` に `hinge.body_relief_clearance: 0.3`(片側)を設定
- `/fit-check` の C カテゴリでこの設計をチェックする
- **原則**: 壁埋込型の蝶番を採用したら、リリーフカットを CAD で **必ず**入れる(後から実物で削るのは再現性を損なう)

### P14. 蝶番側リップの非対称クリアランス忘れ

**症状**: 蓋の蝶番側 (-Y 等) でリップが擦って閉じない、または閉じづらい

**原因**: 蝶番ピンが蓋の Y 位置を拘束するため、蝶番側で印刷誤差を逃がすマージンが必要。全周一律 `fit_clearance` だと不足する。

**対処**:
- `case-config.yaml` の `lip_hinge_side_extra_clearance` を導入(例: 1.1mm)
- 蝶番側総クリア = `fit_clearance` + `lip_hinge_side_extra_clearance`(例: 0.4 + 1.1 = 1.5mm)
- 反対側(ラッチ側)は標準値のままで OK(ラッチ自体の弾性で誤差吸収)
- リップ寸法は蝶番側に向けて中心シフトする実装が必要

## 利用ワークフローの落とし穴

### P9. 段階 4(`/review-fix`)を飛ばす

**症状**: 試作したら干渉、寸法ミス、印刷できない

**原因**: validator の ❌ を見逃して試作に進む

**対処**:
- 段階 4 のゲート(`@.claude/quality-gates.md`)を必ず通過させる
- 「初回 50% → 段階 4 で 80%」のリズムを守る(README「ワークフローのリズム感」参照)
- ❌ がある状態で `/export` を呼ばない

### P10. case-config.yaml を直接編集 → generator.py 再実行を忘れる

**症状**: 値を変えても preview が変わらない

**原因**: 数値編集後に generator を実行していない

**対処**:
- 編集後は **必ず** `python output/design/generator.py` を実行
- `/review-fix` を呼べば自動で再実行される
- generator.py は冪等(同じ input から同じ output)

### P11. ハイブリッドゾーン(case-spec.yaml)を Claude が上書き

**症状**: 利用者が直接編集した内容が消える

**原因**: Claude が次の `/design` 実行時に再上書きしてしまう

**対処**:
- `/design` SKILL.md の「ハイブリッドゾーン」記述を尊重
- 2 回目以降の実行では既存 yaml を読み、利用者編集を優先
- 不安なら `git diff` で変更を確認

### P12. フォント本体を Git にコミット

**症状**: リポサイズが膨らむ、ライセンス違反のリスク

**原因**: `src/fonts/<name>.ttf` を git add してしまう

**対処**:
- 配布禁止フォントは `.gitignore` で除外(`src/fonts/*.ttf`)
- ライセンスファイル(`LICENSE-<name>.txt`)のみ追跡
- 利用者にフォントの個別ダウンロードを案内

### P15. 本体再印刷不可な状況で本体パラメータを変える

**症状**: 段階 4 のフィードバックで本体寸法を変えてしまい、既に印刷済みの本体と組み合わなくなる

**原因**: 印刷時間が長い本体(例: 10 時間)を再印刷したくない状況を考慮していない

**対処**:
- 本体 STL ハッシュ(`md5`/`sha256`)を変更前後で比較し、不変であることを確認
- 蓋のみで吸収できるパラメータ(例: `lid_knuckle_extra_clearance_z`、`fit_clearance` の蓋側のみ縮小)を活用
- generator.py で **本体パラメータと蓋パラメータを明確に分離** し、変更影響範囲をコメントで記す
- `/review-fix` のフィードバック処理で「本体不変か蓋のみ変更か」をユーザーに確認する習慣

### P16. ALLOWLIST に「動作確認後の手削り対応」を暗黙で許容

**症状**: 印刷後にやすり調整を頻繁に求められるケースが増え、再現性が低下

**原因**: `fit_check.py` の `ALLOWLIST` に登録されない CAD 重なりを「実物で削れば OK」として暗黙許容

**対処**:
- 意図的な重なりは `ALLOWLIST` に **必ず登録**(label / max_mm3 / 理由)
- CAD で解消できる場合は解消し、`ALLOWLIST` から削除 + コメントで履歴を残す
- 「明示許容」と「暗黙許容」を区別する。後者は `/fit-check` で検出されるべき
