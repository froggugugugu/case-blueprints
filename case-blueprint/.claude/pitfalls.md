# Pitfalls — 3D プリント設計の落とし穴

このファイルは `case-blueprints` で生成されたプロジェクトにおいて、よくある失敗パターン(pitfall)と対処法を整理する。

実例から抽出した教訓を含む(GPS ロガーケース等)。

---

## 印刷時の落とし穴

### P1. 印刷向きの判断ミス

**症状**: 細部(文字 emboss、薄い壁、フィレット)が初層側にあると失敗しやすい

**原因**:
- 初層は接着力優先で粗くなりがち
- 細部は印刷終盤の方が形状が出やすい

**対処**:
- `case-spec.yaml` の `print_orientation` を見直す
- body は `bottom_down`(底を下)、lid は `top_down`(天を下)が基本
- 細部のある面が **印刷終盤** に来るように設定

### P2. オーバーハング・サポートの見落とし

**症状**: 蝶番ナックル、カラビナタブ、張り出し部位が崩れる

**原因**: 50° 以上のオーバーハングはサポート必須

**対処**:
- `slicer-notes.md` の「サポート」セクションで部位別判断
- 蝶番ナックルの上半分はブリッジング可(短いブリッジは PLA で問題なし)
- ツリーサポート / オーガニックサポートを優先

### P3. フィレット過多

**症状**: 印刷困難、強度低下、寸法ばらつき増加

**原因**: 過大な R を入れすぎ

**対処**:
- 外側角: 2-3mm が標準
- 内側角: 0.5mm 程度
- 手触り重視部位のみ大きめ R(底面エッジなど)

### P4. フォント細部の潰れ

**症状**: body_text feature の文字が読めない、潰れる

**原因**: 層高が大きすぎる、emboss_depth が小さい

**対処**:
- 層高 0.16mm 以下 → 細部が鮮明
- 層高 0.2mm → ほぼ問題なし
- 層高 0.28mm 以上 → 細部潰れの恐れ
- emboss_depth 0.6mm(0.2mm 層 × 3 層)を最低ライン
- 極細フォントは避ける

## 設計時の落とし穴

### P5. 嵌合クリアランス不足/過多

**症状**: 蓋が硬すぎる / ゆるい

**原因**: `lid.fit_clearance` の値

**対処**:
- 0.15 未満 → 固い(やすり調整必要)
- 0.2 → 標準(PLA)
- 0.3 以上 → ゆるい
- PETG は摩擦が大きいので 0.25 推奨

### P6. CAD 上の幾何重なり

**症状**: validator で「○○ mm³ の重なり」を検出

**原因**: 蝶番ナックルなど、意図的にエッジを共有する設計で発生

**対処**:
- 微小な重なり(< 50 mm³)は **実物でやすり調整** で対応
- これは CAD 上の問題で、印刷時の問題ではない
- `slicer-notes.md` の「既知の小さな干渉」セクションに記録

### P7. 内寸計算ミス

**症状**: オブジェクトがケースに入らない、または隙間が大きすぎる

**原因**: 公差・余裕・ケーブル湾曲分の計算漏れ

**対処**:
- 内寸 = オブジェクト寸法 + 公差(`tolerance`) + 余裕(`internal.object_clearance`)
- ケーブルがある場合 `internal.cable_bend_allowance` を追加
- 複数オブジェクト時は配置間隔も加算

### P8. オブジェクト同士の干渉

**症状**: 配置時にコネクタ・ボタン・LED が他のオブジェクトと重なる

**原因**: `input/objects/<id>.yaml` の notes に向きを書いていない

**対処**:
- notes に「正面」「USB ポートの位置」「LED の位置」を明記
- `case-spec.yaml` の `objects[].note` に配置意図を残す
- validator で干渉チェック(features 別)

## 利用ワークフローの落とし穴

### P9. 段階 4(`/review-fix`)を飛ばす

**症状**: 試作したら干渉、寸法ミス、印刷できない

**原因**: validator の ❌ を見逃して試作に進む

**対処**:
- 段階 4 のゲート(`@.claude/quality-gates.md`)を必ず通過させる
- 「初回 50% → 段階 4 で 80%」のリズムを守る(README「ワークフローのリズム感」参照)
- ❌ がある状態で `/export` を呼ばない

### P10. case-config.yaml を直接編集 → generator.py 再実行を忘れる

**症状**: 値を変えても preview が変わらない

**原因**: 数値編集後に generator を実行していない

**対処**:
- 編集後は **必ず** `python output/design/generator.py` を実行
- `/review-fix` を呼べば自動で再実行される
- generator.py は冪等(同じ input から同じ output)

### P11. ハイブリッドゾーン(case-spec.yaml)を Claude が上書き

**症状**: 利用者が直接編集した内容が消える

**原因**: Claude が次の `/design` 実行時に再上書きしてしまう

**対処**:
- `/design` SKILL.md の「ハイブリッドゾーン」記述を尊重
- 2 回目以降の実行では既存 yaml を読み、利用者編集を優先
- 不安なら `git diff` で変更を確認

### P12. フォント本体を Git にコミット

**症状**: リポサイズが膨らむ、ライセンス違反のリスク

**原因**: `src/fonts/<name>.ttf` を git add してしまう

**対処**:
- 配布禁止フォントは `.gitignore` で除外(`src/fonts/*.ttf`)
- ライセンスファイル(`LICENSE-<name>.txt`)のみ追跡
- 利用者にフォントの個別ダウンロードを案内
